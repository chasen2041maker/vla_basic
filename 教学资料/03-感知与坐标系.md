# 阶段 03：感知与坐标系

预估投入 10-15 小时 · 无硬件要求 · 产出：从相机图像算出物体位姿并驱动抓取

## 这个阶段要解决什么

阶段 02 里你用 `data.xpos[body_id]` 直接读物体位置。这是仿真特权，真机没有。

真机上你只有相机图像。把「一张图」变成「物体在机器人基座坐标系下的位姿」，这就是感知。

这个阶段的核心收获不是学会某个算法，是**第一次体会观测噪声**。

## 3.1 相机模型：针孔与内参

相机把三维点投影成二维像素。最常用的模型是针孔模型：

```
u = fx * (X / Z) + cx
v = fy * (Y / Z) + cy
```

其中 `(X, Y, Z)` 是点在相机坐标系下的坐标，`(u, v)` 是像素坐标。

四个参数 `fx, fy, cx, cy` 叫**内参**（intrinsics），通常写成矩阵：

```
K = | fx  0  cx |
    | 0  fy  cy |
    | 0   0   1 |
```

- `fx, fy` 是焦距（以像素为单位），决定视场角
- `cx, cy` 是主点，通常接近图像中心

注意投影里除了 Z——**这意味着从单张图像无法恢复深度**。同一个像素可能来自远处的大物体或近处的小物体。这就是为什么需要深度相机、双目或者已知物体尺寸。

反投影（从像素恢复三维点）需要深度：

```python
import numpy as np


def pixel_to_camera_frame(
    u: float,
    v: float,
    depth: float,
    K: np.ndarray,
) -> np.ndarray:
    """把像素坐标 + 深度反投影成相机坐标系下的三维点。

    depth 是该像素对应的 Z 值（沿相机光轴的距离），
    不是到光心的欧氏距离。这两者容易混淆。
    """
    fx, fy = K[0, 0], K[1, 1]
    cx, cy = K[0, 2], K[1, 2]

    X = (u - cx) * depth / fx
    Y = (v - cy) * depth / fy
    Z = depth
    return np.array([X, Y, Z])
```

## 3.2 外参与手眼标定

内参描述相机自身。**外参**（extrinsics）描述相机在世界里的位置和朝向，也就是 `T_world_camera`。

相机的安装方式分两种，这个区别很重要：

**eye-to-hand（相机固定）** — 相机装在三脚架或天花板上，不随机械臂动。外参 `T_base_camera` 是常量，标定一次就行。

**eye-in-hand（相机在手上）** — 相机装在机械臂末端，随手臂运动。这时 `T_base_camera = T_base_hand @ T_hand_camera`，其中 `T_base_hand` 由 FK 实时算出，`T_hand_camera` 是需要标定的常量。

求出这个常量变换的过程叫**手眼标定**（hand-eye calibration）。经典做法是拿一个标定板，让机械臂摆多个不同姿势，每个姿势记录一对数据（FK 算出的手的位姿，视觉算出的板的位姿），然后解一个 `AX = XB` 形式的方程。

实践中用现成工具：OpenCV 的 `cv2.calibrateHandEye`，或者 ROS 生态的 `easy_handeye`。

> ⚠️ 需核实：`cv2.calibrateHandEye` 的输入约定（是 `T_gripper_base` 还是 `T_base_gripper`）非常容易搞反，用之前一定看官方文档并用已知数据验证。

💡 联系你的经验：标定误差是一种**系统性偏差**，不是随机噪声。它会让你所有的抓取都稳定地偏 3 毫米。这类 bug 在后端里对应的是「配置错了一个常量导致所有请求都算错」——不会随机失败，而是一致地错。找它的方法也类似：用已知真值做端到端校验。

## 3.3 在 MuJoCo 里渲染相机图像

MuJoCo 可以渲染 RGB 和深度图，这让你能在纯仿真里练感知。

先在 XML 里加相机：

```xml
<worldbody>
  <!-- 固定相机（eye-to-hand），俯视桌面 -->
  <camera name="overhead" pos="0.5 0 1.2" euler="0 0 0" fovy="45"/>

  <!-- 装在末端的相机（eye-in-hand），要放在 hand body 内部 -->
  <body name="hand">
    <camera name="wrist" pos="0 0 0.05" euler="0 0 0" fovy="60"/>
  </body>
</worldbody>
```

渲染代码：

```python
"""在 MuJoCo 里渲染 RGB 和深度图，并从中恢复三维点。"""

import mujoco
import numpy as np


class SimCamera:
    """封装 MuJoCo 的离屏渲染，提供 RGB 和深度图。

    MuJoCo 的深度图返回的是归一化深度，需要转换成真实距离。
    这个转换公式依赖 near/far 平面设置，是个容易出错的地方。
    """

    def __init__(
        self,
        model: mujoco.MjModel,
        camera_name: str,
        width: int = 640,
        height: int = 480,
    ):
        self.model = model
        self.width = width
        self.height = height
        self.camera_id = mujoco.mj_name2id(
            model, mujoco.mjtObj.mjOBJ_CAMERA, camera_name
        )
        if self.camera_id < 0:
            raise ValueError(f"找不到相机 {camera_name}")

        self.renderer = mujoco.Renderer(model, height=height, width=width)

    def render_rgb(self, data: mujoco.MjData) -> np.ndarray:
        """渲染 RGB 图像，返回 (H, W, 3) 的 uint8 数组。"""
        self.renderer.update_scene(data, camera=self.camera_id)
        return self.renderer.render()

    def render_depth(self, data: mujoco.MjData) -> np.ndarray:
        """渲染深度图，返回 (H, W) 的真实距离（米）。"""
        self.renderer.enable_depth_rendering()
        self.renderer.update_scene(data, camera=self.camera_id)
        depth = self.renderer.render()
        self.renderer.disable_depth_rendering()
        return depth

    def get_intrinsics(self) -> np.ndarray:
        """从 MuJoCo 相机的 fovy 计算内参矩阵。

        MuJoCo 用垂直视场角（fovy，单位度）定义相机。
        转换成焦距：fy = (height / 2) / tan(fovy / 2)
        假设方形像素，所以 fx = fy。
        """
        fovy_deg = self.model.cam_fovy[self.camera_id]
        fovy_rad = np.deg2rad(fovy_deg)
        fy = (self.height / 2.0) / np.tan(fovy_rad / 2.0)
        fx = fy
        cx = self.width / 2.0
        cy = self.height / 2.0
        return np.array([[fx, 0, cx], [0, fy, cy], [0, 0, 1]])
```

> ⚠️ 需核实：MuJoCo 3.x 的 `Renderer` 深度渲染返回值单位在不同版本间有过变化，有的版本返回归一化值需要自己按 near/far 反算。写完后务必用已知距离的物体验证一次——放一个方块在相机正下方 0.5 米处，看深度图中心的值是不是 0.5。

## 3.4 最简单的物体检测：颜色分割

先不用深度学习。方块是纯红色的，用颜色阈值就能找到它。

```python
"""基于颜色的物体检测。

这是最原始的方法，但它能让你在没有任何模型的情况下走通
「图像 → 三维位置 → 抓取」的完整链路。先跑通链路，再换更好的检测器。
"""

import cv2
import numpy as np


def detect_red_object(rgb: np.ndarray) -> tuple[int, int] | None:
    """在 RGB 图像中找红色物体的像素中心。

    返回 (u, v) 像素坐标，找不到返回 None。

    用 HSV 空间而不是 RGB，因为 HSV 把颜色和亮度分离，
    对光照变化更鲁棒——但也只是「更」鲁棒，不是不受影响。
    """
    hsv = cv2.cvtColor(rgb, cv2.COLOR_RGB2HSV)

    # 红色在 HSV 里横跨 0 度，需要两段范围
    lower1 = np.array([0, 120, 70])
    upper1 = np.array([10, 255, 255])
    lower2 = np.array([170, 120, 70])
    upper2 = np.array([180, 255, 255])

    mask = cv2.inRange(hsv, lower1, upper1) | cv2.inRange(hsv, lower2, upper2)

    # 形态学开运算去掉孤立噪点
    kernel = np.ones((5, 5), np.uint8)
    mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, kernel)

    contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    if not contours:
        return None

    # 取最大轮廓，假设它就是目标物体
    largest = max(contours, key=cv2.contourArea)

    # 面积太小认为是噪声
    if cv2.contourArea(largest) < 100:
        return None

    moments = cv2.moments(largest)
    if moments["m00"] == 0:
        return None

    u = int(moments["m10"] / moments["m00"])
    v = int(moments["m01"] / moments["m00"])
    return u, v
```

完整的「图像到基座坐标」链路：

```python
def locate_object_in_base_frame(
    camera: SimCamera,
    data: mujoco.MjData,
    T_base_camera: np.ndarray,
) -> np.ndarray | None:
    """从相机图像定位红色物体，返回其在机器人基座坐标系的位置。

    这个函数把整条链路串起来：
      渲染 → 检测像素 → 查深度 → 反投影到相机系 → 变换到基座系

    任何一步失败都返回 None。调用方必须处理 None，
    因为「看不见目标」在真机上是常态，不是异常。
    """
    rgb = camera.render_rgb(data)
    detection = detect_red_object(rgb)
    if detection is None:
        return None

    u, v = detection
    depth_map = camera.render_depth(data)
    depth = float(depth_map[v, u])  # 注意索引顺序是 [行, 列] = [v, u]

    # 深度为 0 或异常大说明该像素没打到物体
    if depth <= 0.01 or depth > 10.0:
        return None

    K = camera.get_intrinsics()
    point_camera = pixel_to_camera_frame(u, v, depth, K)
    return transform_point(T_base_camera, point_camera)
```

注意 `depth_map[v, u]` 的索引顺序。图像数组是 `[行, 列]`，而像素坐标习惯写成 `(u, v) = (列, 行)`。这两者顺序相反，是极高频的 bug。

## 3.5 关键实验：注入噪声

这是本阶段最重要的部分。仿真里的感知是「太干净」的，真机不是。

```python
"""给感知结果注入噪声，观察下游抓取的成功率变化。

这个实验的目的是让你亲身体会：一个数学上正确的抓取流程，
在观测有 5 毫米误差时会失败到什么程度。
"""

import numpy as np


class NoisyPerception:
    """在真值上叠加噪声，模拟真实感知误差。

    分两种噪声，它们的性质完全不同：

    - bias（系统偏差）：模拟标定误差，每次都是同一个方向。
      这类误差可以通过重新标定消除，但如果你不知道它存在，
      会一直稳定地偏。

    - noise（随机噪声）：模拟传感器抖动，每次不同。
      这类误差无法消除，只能通过多次观测取平均来减小。
    """

    def __init__(
        self,
        bias: np.ndarray | None = None,
        noise_std: float = 0.002,
        detection_failure_rate: float = 0.05,
        rng: np.random.Generator | None = None,
    ):
        self.bias = bias if bias is not None else np.zeros(3)
        self.noise_std = noise_std
        self.detection_failure_rate = detection_failure_rate
        self.rng = rng or np.random.default_rng()

    def observe(self, true_position: np.ndarray) -> np.ndarray | None:
        """返回带噪声的观测，有一定概率完全检测失败。"""
        if self.rng.random() < self.detection_failure_rate:
            return None

        noise = self.rng.normal(0.0, self.noise_std, size=3)
        return true_position + self.bias + noise
```

**必做实验：** 用阶段 02 的 pick-and-place 流程，把真值读取换成 `NoisyPerception`，跑 50 次，统计成功率。

| 配置 | 预期成功率 |
|---|---|
| 无噪声（真值） | 接近 100% |
| `noise_std=0.002`（2mm 抖动） | 明显下降 |
| `noise_std=0.005`（5mm 抖动） | 大幅下降 |
| `bias=[0.003, 0, 0]`（3mm 系统偏差） | 稳定地偏向一侧失败 |
| `detection_failure_rate=0.1` | 10% 的任务直接开始不了 |

跑完这个实验你会得到几个重要认识：

**几毫米就足以毁掉抓取。** 方块 5 厘米宽，夹爪开口可能只比它宽 1 厘米，5 毫米误差就占了一半余量。

**系统偏差和随机噪声的失败模式不同。** 前者是一致地偏，后者是随机地时好时坏。定位问题时先判断是哪一类——如果每次都朝同一方向失败，去查标定；如果随机失败，去查传感器或者加滤波。

**「看不见」必须当成正常分支处理。** 你的 `move_to` 在检测失败时该怎么办？重试几次？换个视角再看？还是报告给人？这是阶段 04 和 08 的核心问题。

💡 联系你的经验：这对应文本 Agent 里的工具调用失败处理，但更严酷。工具调用失败可以原样重试，因为世界没变。抓取失败后物体可能已经被推歪了，重试的初始条件和第一次不同。

## 3.6 现代感知方案概览

颜色分割只能用于教学。真实项目用这些，你需要知道它们各自解决什么问题：

| 方案 | 输入 | 输出 | 适用 |
|---|---|---|---|
| **AprilTag / ArUco** | RGB | 标记的 6D 位姿，精度高 | 标定、已知物体上贴码 |
| **YOLO / DETR** | RGB | 2D 检测框 + 类别 | 找到物体在哪，但没有 6D 位姿 |
| **SAM / SAM2** | RGB (+提示) | 分割掩码 | 精确的物体轮廓，可组合深度算位姿 |
| **FoundationPose / MegaPose** | RGB-D + 物体网格 | 6D 位姿，零样本 | 已知三维模型的物体位姿估计 |
| **GraspNet / AnyGrasp** | 点云 | 一组候选抓取位姿 | 直接输出「怎么抓」，不需要物体模型 |
| **开放词汇检测（如 OWL-ViT）** | RGB + 文本 | 检测框 | 用自然语言指定目标，适合 LLM 编排 |

对你的路径，最值得先了解的是最后一类——**开放词汇检测**。因为它接受文本查询，能和你的 agent 天然衔接：LLM 说「找红色的杯子」，检测器直接吃这个字符串。

一个可选的加分实验：把 `detect_red_object` 换成 OWL-ViT 或 Grounding DINO，用文本 prompt 检测。这一步做完，你的感知层就能被 LLM 直接驱动了。

> ⚠️ 需核实：这些模型的 API 和权重发布方式变化很快，用之前查 Hugging Face 上的最新用法。

## 3.7 抓取位姿：不只是位置

到目前为止你只用了位置。但抓一个杯子，从上面抓和从侧面抓完全不同。

完整的抓取位姿是 6D：位置 + 朝向。还要加上夹爪开口宽度，所以实践中常说 7 维。

对简单的方块，一个够用的启发式规则：

```python
def compute_top_down_grasp(
    object_position: np.ndarray,
    approach_height: float = 0.10,
) -> tuple[np.ndarray, np.ndarray]:
    """计算自上而下的抓取位姿。

    返回 (接近位置, 抓取位置)。

    自上而下（top-down）是最简单也最鲁棒的抓取方式，
    因为它不需要知道物体的朝向。代价是无法抓取需要侧向
    接近的物体（比如书架上的书）。

    实际的抓取朝向还需要绕 Z 轴的旋转角，对方块来说
    可以任意（正方形对称），对长条物体则需要对齐长边。
    """
    approach = object_position + np.array([0.0, 0.0, approach_height])
    grasp = object_position.copy()
    return approach, grasp
```

真实系统里这一步由 GraspNet 这类模型完成，它直接从点云输出一组候选抓取，每个带一个置信度分数。你的上层逻辑负责从候选里挑一个可执行的（IK 有解、不碰撞、置信度够高）。

💡 联系你的经验：这是一个典型的「候选生成 + 过滤 + 排序」流程，和你在推荐系统或者检索里做的事结构一样。区别是过滤条件里有物理可行性。

## 3.8 本阶段大作业

把阶段 02 的 pick-and-place 改造成完全基于视觉：

要求：

1. 不再调用 `data.xpos` 读物体真值
2. 物体位置从相机图像估计得到
3. 感知层用 `NoisyPerception` 包一层，可配置噪声等级
4. 实现「多次观测取平均」来对抗随机噪声
5. 实现检测失败时的重试逻辑（换视角或者多等几帧）
6. 跑 50 次统计成功率，做出一张噪声等级对成功率的表

第 4 条的实现提示：

```python
def observe_with_averaging(
    perception,
    true_position: np.ndarray,
    num_samples: int = 5,
    max_attempts: int = 10,
) -> np.ndarray | None:
    """多次观测取中位数，减小随机噪声影响。

    用中位数而不是均值，因为中位数对离群值（偶发的错误检测）
    更鲁棒。均值会被一个严重错误的观测拉偏。

    注意这个方法对系统偏差完全无效——偏差在每次观测里都一样，
    取平均后还在。只有重新标定能解决它。
    """
    samples = []
    attempts = 0
    while len(samples) < num_samples and attempts < max_attempts:
        attempts += 1
        obs = perception.observe(true_position)
        if obs is not None:
            samples.append(obs)

    if not samples:
        return None
    return np.median(np.array(samples), axis=0)
```

注意文档字符串里那句提醒：**取平均能压随机噪声，但对系统偏差无效。** 这个区分是本阶段最有价值的认知之一。
