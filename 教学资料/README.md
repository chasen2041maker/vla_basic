# 具身智能 / VLA 入门教程

## 这份教程是给谁的

假设你：

- Python 熟练，能读写工程代码
- C++ 会一些，能看懂，不要求能写高性能代码
- 做过 LLM Agent（工具调用、任务编排、状态管理）
- 机器人零基础：不懂运动学、没碰过 ROS、没训过策略模型

如果这是你，这份教程从你已有的地方出发，不从大学一年级讲起。

## 这份教程不教什么

明确跳过，因为不在这条路径上：

- 控制理论（PID 调参、阻抗控制、力控）
- 嵌入式与固件开发（MCU、驱动、总线）
- 腿足机器人的 locomotion 与步态
- SLAM 的内部算法原理
- 强化学习的深水区（只讲概念，不调参）
- 点云算法与三维重建

这些每一样都是几年的专业方向。业余投入进去只会得到皮毛，而且上层岗位不需要。需要的时候，你会知道去找谁。

## 核心判断：为什么从 Agent 切入具身是可行的

具身智能的技术栈从下往上：

| 层 | 内容 | 语言 | 你的距离 |
|---|---|---|---|
| 硬件/固件 | 电机驱动、编码器、EtherCAT/CAN | C | 远，跳过 |
| 实时控制 | 关节 PID、力控，1kHz 控制环 | C++ | 远，跳过 |
| 运动规划 | 逆运动学、轨迹规划、碰撞检测 | C++/Python | 需要会用 |
| 感知 | 3D 视觉、位姿估计、SLAM | Python/C++ | 需要会用 |
| 策略（小脑） | VLA、模仿学习、diffusion policy | Python | 需要理解 |
| 任务规划（大脑） | LLM 拆解任务、调用技能、失败重规划 | Python | **你已经在做** |

最上面一层就是 Agent。工具从 `query_stock_price()` 换成 `pick(object_id)`，返回值从 JSON 换成「成功 / 失败 / 物体滑落」。

所以你的起点不是零，是换一套工具集，再往下补两层到「会用」的程度。

## 具身与文本 Agent 的四个根本差异

这四条是整份教程的主线。技术细节会变，这四条不会。

**1. 世界状态不可回滚。** 后端事务失败可以 rollback，消息可以重投。机器人把杯子打翻了，没有 rollback。你熟悉的幂等/重试机制的前提是「操作可安全重复执行」，这个前提在物理世界直接失效——重试一次抓取，物体已经不在原位了。

**2. 观测不完整且带噪声。** 查数据库拿到的是真值。机器人的每个「观测」都是估计：相机测的位姿有误差，力矩传感器有漂移，编码器有累积偏差。你不知道有没有抓稳，只能从不可靠信号里推断。

**3. 时间是硬约束。** 后端延迟 200ms 是体验问题。控制环 1kHz 意味着 1ms 内必须算完，超了机器人会抖动甚至自激振荡。这不是性能优化，是正确性条件。

**4. 失败是常态，不是异常。** 你的工具调用成功率 88% 算不错。机器人抓取策略在真机上三四成成功率是正常水位。系统设计必须假设大部分动作会失败。

## 八个阶段

| 阶段 | 主题 | 预估投入 | 硬件要求 | 产出 |
|---|---|---|---|---|
| 01 | 环境与心智模型 | 6-10h | 无 | 仿真里的机械臂动起来 |
| 02 | 运动学与控制接口 | 10-15h | 无 | 手写 IK 完成 pick-place |
| 03 | 感知与坐标系 | 10-15h | 无 | 从相机图像算出物体位姿 |
| 04 | Agent 驱动仿真 | 10-15h | 无 | LLM 编排完成多步任务 |
| 05 | 模仿学习 | 15-25h | GPU | 采数据训 ACT 并评估 |
| 06 | VLA 模型 | 15-25h | GPU | 跑通 OpenVLA 推理与微调 |
| 07 | 真机与 sim2real | 20-40h | SO-101 | 真机完成抓取任务 |
| 08 | Agent 运行时治理接入具身 | 不设上限 | 可选 | 你自己的开源项目 |

阶段 01 到 04 零硬件成本，纯软件，可以在任何笔记本上做（04 需要一个 LLM API key）。

阶段 05 到 06 需要 GPU。没有本地卡就租云上按小时实例，比买卡划算。

阶段 07 需要买 SO-101，几千块。

**先做完 01 和 02 再决定要不要继续。** 这两个阶段花不了几个周末，做完你会知道自己对这件事的兴趣是真的还是想象的。

## 关键提醒：反馈是稀疏的

如果你是被「代码驱动真实机械」这件事吸引进来的，需要提前知道那个瞬间前面是什么样：

标定两个下午，坐标系对不上。采 50 条演示数据，手腕酸，十几条因为抖动废掉。训练几小时。部署真机，成功率 30%，看着机械臂一次次擦着目标过去。改数据、重训，还是 35%。第三周某个下午，它连续成功五次，你会站起来。

具身的反馈不是「更可见」，是**更稀疏但峰值更高**。中间几周的挫败感比调后端 bug 强得多，因为物理世界不给你 stack trace——你甚至不知道该怪数据、怪标定还是怪策略。

后端的反馈是密的：跑通一个测试、修好一个竞态、看到 P99 降下来。峰值低，频率高。

两种驱动模式适合不同的人，和「哪个更高级」无关。你需要知道自己是哪一种，而这个只能试出来。

## 阶段 08 才是重点

阶段 01 到 07 是补课，做的都是别人做过的事，而且做得比你专业。

阶段 08 是唯一别人做不出、只有你能做的部分。

具身领域现在的人大多是算法背景，关心策略成功率能不能从 35% 提到 50%。很少有人在系统层面问：失败后世界状态怎么办、哪些动作不可逆需要人确认、执行过程怎么留证、长任务挂起后怎么恢复。

而这些正是你在 Agent 运行时里已经解决过的问题。「执行到一半发现杯子里有水，挂起问人要不要继续」——这就是 HITL elicitation，只是工具从 shell 命令换成了机械臂。

所以你的定位不是「转行做具身」，是**把 Agent 运行时的工程能力带进具身**。这也是为什么要跳过控制理论——那会让你变成一个平庸的控制工程师，而不是一个稀缺的 Agent 基础设施工程师。
