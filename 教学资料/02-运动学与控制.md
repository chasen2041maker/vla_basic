## 这个阶段要解决什么

阶段 01 结束时你能控制关节角度。但你想表达的是「把手移到杯子那里」，杯子的位置是三维坐标，不是关节角度。

这两者之间的转换就是运动学。

## 2.1 正运动学与逆运动学

**正运动学（FK）**：给定关节角度，算出末端在哪。唯一解，简单，MuJoCo 每步自动算好，读 `data.xpos` 就有。

**逆运动学（IK）**：给定末端目标位置，求关节角度。这是难的方向，原因：

- 可能无解（目标在工作空间之外，手臂不够长）
- 可能多解（7 自由度机械臂到同一个点有无穷多种姿势）
- 没有通用闭式解，一般用数值迭代

💡 联系你的经验：FK 像正向计算哈希，确定且唯一。IK 像找一个原像，可能不存在、可能有很多个，只能搜索。

## 2.2 位姿的表示

「末端在哪」需要 6 个数：位置 3 个（x, y, z），姿态 3 个自由度。位置没有歧义，姿态有多种表示方式。

| 表示 | 维度 | 优点 | 缺点 |
|---|---|---|---|
| 欧拉角 (roll, pitch, yaw) | 3 | 直观，人能读懂 | 万向锁、顺序有歧义 |
| 旋转矩阵 | 9 | 无奇异、可直接相乘 | 冗余，需保持正交 |
| 四元数 (w, x, y, z) | 4 | 无万向锁、插值平滑 | 不直观，有双覆盖（q 和 -q 同姿态） |
| 轴角 / 旋转向量 | 3 | 紧凑、便于表达误差 | 零旋转附近有数值问题 |

**万向锁**是欧拉角的根本缺陷：当 pitch 接近 ±90° 时，roll 和 yaw 变得不可区分，失去一个自由度。这就是为什么机器人和图形学普遍用四元数。

MuJoCo 用四元数（`data.xquat`，顺序是 `w, x, y, z`）。注意有些库用 `x, y, z, w`（比如 scipy 的 `Rotation`），转换时容易搞错顺序，这是高频 bug。

```python
import numpy as np
from scipy.spatial.transform import Rotation

# MuJoCo 是 (w, x, y, z)，scipy 是 (x, y, z, w)
def mujoco_quat_to_scipy(q_mujoco: np.ndarray) -> Rotation:
    """MuJoCo 四元数转 scipy Rotation 对象。"""
    w, x, y, z = q_mujoco
    return Rotation.from_quat([x, y, z, w])


def scipy_to_mujoco_quat(rot: Rotation) -> np.ndarray:
    """scipy Rotation 转 MuJoCo 四元数。"""
    x, y, z, w = rot.as_quat()
    return np.array([w, x, y, z])
```

把这两个函数放进你的工具库，以后一直会用。

## 2.3 坐标系与变换

机器人系统里同时存在很多坐标系：

- **世界系（world）**：全局参考，通常固定在地面某点
- **基座系（base）**：机器人底座，机械臂固定时常和世界系重合
- **末端系（end-effector / tool）**：手爪中心，随机械臂运动
- **相机系（camera）**：相机光心，Z 轴通常朝前
- **物体系（object）**：物体自身中心

同一个点在不同坐标系里坐标不同。「杯子在 (0.3, 0.1, 0.8)」这句话不完整，必须说清是在哪个坐标系下。

变换用齐次矩阵表示，4×4：

```
T = | R  t |     R 是 3×3 旋转矩阵，t 是 3×1 平移向量
    | 0  1 |
```

关键性质：变换可以链式相乘。`T_world_object = T_world_camera @ T_camera_object`。下标读法是「从右下标系到左下标系」，相邻的下标必须对得上——这是检查自己有没有写错的最快方法。

```python
import numpy as np


def make_transform(rotation_matrix: np.ndarray, translation: np.ndarray) -> np.ndarray:
    """构造 4x4 齐次变换矩阵。"""
    T = np.eye(4)
    T[:3, :3] = rotation_matrix
    T[:3, 3] = translation
    return T


def invert_transform(T: np.ndarray) -> np.ndarray:
    """求齐次变换的逆。

    不要用 np.linalg.inv，利用旋转矩阵正交的性质更快且数值更稳。
    """
    R = T[:3, :3]
    t = T[:3, 3]
    T_inv = np.eye(4)
    T_inv[:3, :3] = R.T
    T_inv[:3, 3] = -R.T @ t
    return T_inv


def transform_point(T: np.ndarray, point: np.ndarray) -> np.ndarray:
    """用变换矩阵变换一个三维点。"""
    homogeneous = np.append(point, 1.0)
    return (T @ homogeneous)[:3]
```

💡 联系你的经验：坐标系不匹配是具身里最常见的 bug 来源，性质上类似时区错误——数值看着合理，但全错。养成在变量名里写清坐标系的习惯（`cup_pos_in_base` 而不是 `cup_pos`），和你在后端里区分 UTC 和本地时间是同一个纪律。

## 2.4 雅可比矩阵：IK 的核心工具

雅可比矩阵 J 描述**关节速度到末端速度的线性映射**：

```
v_end = J(q) @ q_dot
```

其中 `v_end` 是 6 维（3 个线速度 + 3 个角速度），`q_dot` 是关节速度，J 的形状是 `(6, n_joints)`。

J 依赖当前关节角度 q，所以每次迭代都要重算。

IK 的数值解法思路很直接：

1. 当前末端位姿和目标位姿的差是 `error`
2. 用 J 的伪逆求出需要的关节增量：`dq = J_pinv @ error`
3. 走一小步：`q = q + alpha * dq`
4. 重复直到误差足够小

这本质上是梯度下降。

MuJoCo 提供 `mj_jac` 系列函数直接算雅可比：

```python
import mujoco
import numpy as np


def compute_jacobian(
    model: mujoco.MjModel,
    data: mujoco.MjData,
    body_id: int,
) -> np.ndarray:
    """计算指定 body 的 6xnv 雅可比矩阵。

    返回的矩阵上 3 行是位置雅可比，下 3 行是姿态雅可比。
    调用前必须保证 data 的运动学已更新（mj_forward 或 mj_step 之后）。
    """
    jacp = np.zeros((3, model.nv))  # 位置部分
    jacr = np.zeros((3, model.nv))  # 姿态部分
    mujoco.mj_jacBody(model, data, jacp, jacr, body_id)
    return np.vstack([jacp, jacr])
```

## 2.5 手写一个 IK 求解器

创建 `code/02_ik_solver.py`：

```python
"""基于雅可比伪逆的数值逆运动学求解器。

这是最基础的 IK 实现。生产环境会用 mink、pinocchio 或
MuJoCo 自带的 mink 集成，但手写一遍能让你理解它为什么会失败。
"""

from dataclasses import dataclass

import mujoco
import numpy as np


@dataclass
class IKResult:
    """IK 求解结果。

    success 为 False 时 qpos 仍然是最后一次迭代的值，
    调用方需要自己决定是否使用。
    """

    success: bool
    qpos: np.ndarray
    position_error: float
    iterations: int


def solve_ik_position(
    model: mujoco.MjModel,
    data: mujoco.MjData,
    body_id: int,
    target_pos: np.ndarray,
    *,
    max_iterations: int = 200,
    tolerance: float = 1e-3,
    step_size: float = 0.5,
    damping: float = 1e-4,
) -> IKResult:
    """求解使指定 body 到达目标位置的关节角度（只管位置，不管姿态）。

    使用阻尼最小二乘（DLS）而不是纯伪逆，避免在奇异位形附近
    产生爆炸性的关节速度。damping 越大越稳定但收敛越慢。

    注意：这个函数会修改 data 的状态。调用方如果需要保留原状态，
    应该先备份 data.qpos。
    """
    for iteration in range(max_iterations):
        # 更新运动学，让 data.xpos 反映当前 qpos
        mujoco.mj_forward(model, data)

        current_pos = data.xpos[body_id].copy()
        error = target_pos - current_pos
        error_norm = float(np.linalg.norm(error))

        if error_norm < tolerance:
            return IKResult(True, data.qpos.copy(), error_norm, iteration)

        # 只取位置雅可比的 3 行
        jacp = np.zeros((3, model.nv))
        jacr = np.zeros((3, model.nv))
        mujoco.mj_jacBody(model, data, jacp, jacr, body_id)

        # 阻尼最小二乘：dq = J^T (J J^T + lambda I)^-1 e
        JJt = jacp @ jacp.T
        damped = JJt + damping * np.eye(3)
        dq = jacp.T @ np.linalg.solve(damped, error)

        # 走一小步
        data.qpos[:] += step_size * dq

        # 关键：夹到关节限位内，否则会求出物理上不可能的解
        clamp_to_joint_limits(model, data)

    mujoco.mj_forward(model, data)
    final_error = float(np.linalg.norm(target_pos - data.xpos[body_id]))
    return IKResult(False, data.qpos.copy(), final_error, max_iterations)


def clamp_to_joint_limits(model: mujoco.MjModel, data: mujoco.MjData) -> None:
    """把 qpos 夹到模型定义的关节范围内。

    只处理有限位的关节（jnt_limited 为真）。自由关节和无限位
    的旋转关节跳过。
    """
    for joint_index in range(model.njnt):
        if not model.jnt_limited[joint_index]:
            continue
        qpos_addr = model.jnt_qposadr[joint_index]
        low, high = model.jnt_range[joint_index]
        data.qpos[qpos_addr] = np.clip(data.qpos[qpos_addr], low, high)
```

用它做一次求解：


## 2.6 生产环境用什么

手写 IK 是为了理解原理。真实项目用现成库：

| 库 | 语言 | 特点 |
|---|---|---|
| **mink** | Python | 基于 MuJoCo 的微分 IK，支持多任务加权、限位约束，推荐 |
| **pinocchio** | C++/Python | 高性能刚体动力学库，工业界常用 |
| **Drake** | C++/Python | 丰富的规划与优化，学习曲线陡 |
| MuJoCo `mj_inverse` | C/Python | 逆动力学（求力矩），不是逆运动学，别搞混 |

推荐 mink，因为它和 MuJoCo 无缝集成，而且支持你后面会需要的东西：同时约束位置和姿态、避开障碍、保持某个关节接近某个值。

## 2.7 从 IK 到可执行的动作

IK 给你一个目标关节角度，但你不能直接把 `qpos` 赋值过去——那是「传送」，不是运动。真实机器人必须连续地走过去。

所以需要**轨迹插值**：

```python
import numpy as np


def interpolate_joint_trajectory(
    q_start: np.ndarray,
    q_end: np.ndarray,
    num_steps: int,
) -> np.ndarray:
    """生成关节空间的线性插值轨迹。

    返回形状 (num_steps, n_joints) 的数组。

    这是最简单的插值。实际使用中线性插值会导致起停时的
    加速度突变（jerk），真实机器人上会抖动。
    """
    alphas = np.linspace(0.0, 1.0, num_steps)
    return np.array([(1 - a) * q_start + a * q_end for a in alphas])


def interpolate_smooth(
    q_start: np.ndarray,
    q_end: np.ndarray,
    num_steps: int,
) -> np.ndarray:
    """用五次多项式做平滑插值，起止速度和加速度都为零。

    这是最小 jerk 轨迹的常用近似，真实机器人上明显比线性插值平稳。
    """
    t = np.linspace(0.0, 1.0, num_steps)
    # 五次多项式 s(t) = 6t^5 - 15t^4 + 10t^3，满足 s(0)=0, s(1)=1,
    # s'(0)=s'(1)=0, s''(0)=s''(1)=0
    s = 6 * t**5 - 15 * t**4 + 10 * t**3
    return np.array([(1 - si) * q_start + si * q_end for si in s])
```

**动手对比：** 用两种插值分别驱动 Panda 走同一段路径，观察查看器里的差异。线性插值在起止点会有明显的顿感。

💡 联系你的经验：这一步在后端里没有对应物。你不需要「平滑地」把一个值从 A 改成 B。物理世界有惯性，突变的指令会产生冲击。
