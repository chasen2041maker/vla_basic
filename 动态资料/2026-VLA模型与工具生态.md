## 2. 入手建议

**从 OpenVLA 开始。** 理由：

- 权重完全公开，不需要申请
- 代码可读，社区文档足够
- 7B 规模在单张 24G 卡上能用 LoRA 微调
- LeRobot 生态里有现成的接入路径

π0 值得读论文理解思路（flow matching 输出连续动作比离散化更优雅），但工程复杂度更高，不适合作为第一个上手的模型。

GR00T 面向人形机器人，如果你的目标是桌面机械臂，暂时用不上。

## 3. 安装与环境坑

```bash
pip install transformers accelerate peft
```

- **flash-attn** 在 Windows 上编译经常失败。装不上就用 `attn_implementation="eager"` 退化到普通注意力，速度慢一些但功能正常
- OpenVLA 需要 `trust_remote_code=True`，因为它的模型类不在 transformers 主干里
- `predict_action` 的接口签名和 `unnorm_key` 的可选值在版本间变过。以仓库当前 README 为准

> ⚠️ 需核实：上面这三条都是版本相关的。transformers 每个 minor 版本都可能改动 vision2seq 相关的接口。

## 4. 部署与推理工具

VLA 推理用不上 vLLM（原因见课程正文的类比失效小节）。实际会用的：

| 工具 | 适用 | 状态 |
|---|---|---|
| **torch.compile** | 最省事，PyTorch 原生，可观的加速 | 稳定，首选 |
| **TensorRT / TensorRT-LLM** | NVIDIA 平台，延迟最低 | 部署复杂度高 |
| **ONNX Runtime** | 跨平台，边缘设备 | 算子支持要逐个确认 |
| **量化（INT8/INT4）** | 边缘设备上是必需的 | 精度损失需要实测 |

> ⚠️ 需核实：这几个工具对 VLA 类模型（视觉 + 语言 + 自定义 action head）的支持程度差异很大，尤其是 ONNX 导出经常在自定义算子上卡住。用之前先查有没有人成功导出过同一个模型。

## 5. 数据集

| 数据集 | 规模 | 说明 | 我是否用过 |
|---|---|---|---|
| **Open X-Embodiment (OXE)** | 22 种机器人、100 万条以上轨迹 | 跨本体训练的标准数据源，OpenVLA 在此训练 | 否 |
| **Bridge / BridgeData V2** | 数万条 | OXE 的组成部分之一，`unnorm_key="bridge_orig"` 就是指它 | 否 |
| **DROID** | 数万条 | 大规模真机操作数据 | 否 |
| **LeRobot 社区数据集** | 各种 | Hugging Face 上社区上传的 SO-100/SO-101 数据 | 否 |

> ⚠️ 需核实：数据集的规模数字和访问方式（是否需要申请、下载体积）都会变。
