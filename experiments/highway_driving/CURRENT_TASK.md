## HighwayEnv 在路线里的位置（2026-10-07 记录）

**问：HighwayEnv 只是个普通的入门项目，对入门整个智驾有帮助吗？**

**答：** 它确实是很简单的入门模拟器，对“整个智驾”帮助有限，但对**规划、控制、闭环评测**这一段帮助很实在。所以路线里只给它阶段 1 的 2–3 天和阶段 2 的一个小项目，之后就换真实数据。

### 它覆盖了智驾的哪几层

| 层（见 [系统全景](../../docs/SYSTEM_MENTAL_MODEL.md)） | HighwayEnv 里有吗 |
| --- | --- |
| 传感器、数据对齐、感知 | ❌ 没有。模拟器直接给出完美的车辆状态表 |
| 预测（别的车接下来怎么走） | ❌ 基本没有 |
| 规划 / 决策 | ✅ 有，简化版 |
| 动作接口、控制器 | ✅ 有，简化版 |
| 车辆运动 | ✅ 有，自行车模型（比真车简单很多） |
| 闭环评测 | ✅ 有 |

它只教了后半条链，前半条（感知、真实数据）没有碰。

### 在真实工作里用得上的

- **IDM 跟车模型**（阶段 1 第 5 项）不只是玩具：nuPlan 的基线规划器 `IDMPlanner` 和闭环仿真里“会反应的背景车” `IDMAgents` 都基于 IDM；Waymo 的仿真器 Waymax 里也有 IDM 驱动的背景车。阶段 3 会在 nuPlan 里再见到它。
- **闭环骨架**：观察 → 决策 → 控制 → 运动 → 新观察。端到端模型、VLA 最后也要接回这条链。
- **评测方法**：固定种子、调参场景和测试场景分开、看结束原因、开环和闭环分开。这是仿真评测岗位天天做的事。
- **基本概念**：时间和频率、动作的层级（高层指令 / 轨迹 / 直接控制）。做哪个方向都要用。

### 它教不了的（阶段 3 和更远的方向补）

相机、图像、几何、多传感器对齐；真实数据的噪声、缺帧、坐标转换；地图和路线；预测的不确定性；端到端模型和 VLA。

### 对求职的意义

只写“学过 HighwayEnv”没有分量。阶段 2 的作品要讲成：**“写了一个规则规划器，搭了一套多种子闭环评测，和强化学习做了对比，分析了失败案例。”** 这是仿真评测、规划方向关心的能力，模拟器只是工具。

### 结论

HighwayEnv 的价值主要在 IDM / MOBIL 和阶段 2 的评测项目。阶段 1 剩下的项目里，第 6、8 项看大意即可，把时间留给第 5 项和阶段 2。不要在它上面停太久，尽快进入真实数据。

### 分工与每课流程

- **学习者手写**：A 的核心算法；B 的指标计算和调度核心逻辑；C 的提示词、输入格式和评测逻辑；D 的模型、训练循环和数据挑选逻辑。
- **助手写**：画图、网页、样板代码；负责仓库结构、代码审查和提交；推送由学习者执行。助手在云端无法运行 CARLA，CARLA 代码在学习者本机验证。
- 每课：概念（短）→ 参考实现（分段讲）→ 手敲 → **先预测再运行** → 改一处看变化 → 助手审查并提交。学习者只贴输出时，助手先问看法；解释和结论由学习者写；卡住分三级提示；每块结束埋 bug 排查 + 面试式追问。
- 讲法（2026-10-11 实际有效的做法）：一次一步，写清文件、行号、改前改后、命令、预期输出；用表格对比数字（例如转角 0.1 / 0.2、车速 10 / 20 的直径和用时）；学习者猜错时给一个小实验让他自己验证；学习者说“讲不清楚”就只讲当前问题、换成日常比喻；学习者明确要“直接给我”时直接给代码并逐行说明。
- 提交与推送：助手在学习者电脑上提交，学习者执行 `git push`，助手用 `git ls-remote` 核对；不索要 GitHub 凭据。

## 阶段 3 预告

开始前再选数据集，核对硬件、硬盘空间和数据申请条件。候选：nuPlan、Waymo Open Motion、nuScenes 的轨迹预测 / 规划任务。

大致顺序：

1. 读懂数据，弄清时间、坐标、字段。
2. 做最简单的预测基线，比如“按当前速度直线外推”。
3. 再做一个小模型。
4. 比较开环指标（预测和真实轨迹差多少），再看闭环表现。
