# 具身智能 / VLA 个人学习仓库

这不是一份写好的教程，是一套会随学习生长的知识系统。

## 这份仓库是给谁的

假设你：

- Python 熟练，能读写工程代码
- C++ 会一些，能看懂，不要求写高性能代码
- 做过 LLM Agent（工具调用、任务编排、状态管理）
- 机器人零基础：不懂运动学、没碰过 ROS、没训过策略模型

## 三层结构

内容分几种，不要混在一起：

| 目录 | 回答的问题 | 特点 |
|---|---|---|
| `课程/` | 这个知识是什么 | 稳定，不常改 |
| `实验/` | 我实际做了什么 | 每做一个实验加一篇 |
| `学习记录/` | 我现在掌握到什么程度 | 持续更新 |
| `论文笔记/` | 这篇论文说了什么 | 读一篇加一篇 |
| `动态资料/` | 当前生态是什么样 | 易过时，单独隔离 |
| `snippets/` | 实验用的少量代码 | 不做成可安装包 |

`动态资料/` 单独存在的理由：模型清单、显存要求、框架 API 这类信息几个月就过时。把它们和稳定知识分开，整份课程才不会每半年失效一次。

## 学习闭环

每个阶段不是「读完」，是走完五步：

```
读懂概念
  ↓
跑通最小实验
  ↓
主动修改一个参数
  ↓
故意制造一个失败
  ↓
不看文档解释失败原因
```

以 IK 为例：

- **只读完** — 「我知道 IK 是根据末端位置求关节角」。这只是见过。
- **跑通** — 输入目标位置，机械臂能到达。这是会用。
- **修改** — 改 damping、step size、初始关节角。这是开始理解。
- **制造失败** — 不可达目标、奇异位形、越过关节限位。这是理解边界。
- **独立解释** — 说明为什么失败，以及该改目标、改约束还是改算法。这才接近掌握。

跑通就往下走，会积累出一种「学过但说不清」的状态。故障实验是这套系统里最重要的部分。

## 为什么是这个顺序

早期版本的路线是「机器人基础 → 感知 → Agent → 模型」，中间缺了两层，会导致一个具体问题：在还没分清「哪个问题属于 IK、哪个属于轨迹、哪个属于夹爪、哪个才真的属于任务规划」的时候，就开始用已有的 Agent 思维解释所有具身问题。

所以补了两个阶段：

**阶段 03（轨迹与闭环控制）** — IK 只解决「终点关节角是什么」，不解决「中间怎么安全走过去」。这两件事的区别必须在引入感知之前搞清楚。

**阶段 05（确定性操作状态机）** — 不用大模型，纯 Python 状态机跑通 pick-place。这一步能让你明确哪些问题 LLM 根本不该处理。做完它再进阶段 06，你不会把所有问题都丢给大模型。

调整后的顺序：

```
机器人基础 → 坐标与运动 → 控制与轨迹 → 感知
→ 确定性闭环操作 → Agent 编排 → 模仿学习 → VLA → 真机
→ 结合自身优势探索治理方向
```

## 掌握级别

具身的知识面很宽，不分级会失去重点。每个知识点标一个级别：

- `[MUST]` 必须真正掌握——能解释、能运行、能修改、能诊断失败
- `[UNDERSTAND]` 能解释原理并会使用
- `[AWARE]` 知道存在，需要时再深入

### 必须掌握

MuJoCo 的 `qpos/qvel/ctrl` · position/velocity/torque 的区别 · 坐标系与齐次变换 · FK / 雅可比 / IK · 轨迹与控制频率 · 相机内外参 · 深度反投影 · 动作空间 · observation-action-episode · 闭环 observe-act-verify · BC / ACT / VLA 的核心差异 · sim2real 的基本问题

### 能解释并会使用

PID 直觉 · 碰撞规划 · Diffusion Policy · ROS 2 的基本分层 · 动作归一化 · LoRA 微调 · 多任务策略 · 置信度与不确定性

### 知道存在即可

完整刚体动力学推导 · 李群李代数深度理论 · MPC · 阻抗与导纳控制的完整推导 · SLAM 内部算法 · 点云配准深水区 · 强化学习调参 · 电机固件与实时总线

## 控制知识的边界

不学完整的控制理论，但**不能完全跳过**。跳过会在学 VLA 时产生误解——比如不理解为什么策略输出不能直接发给电机，或者为什么推理 10Hz 不等于控制器也只跑 10Hz。

最低必要的控制知识按级别划分：

| 内容 | 掌握程度 |
|---|---|
| 开环与闭环 | 必须掌握 |
| position / velocity / torque 控制 | 必须掌握 |
| P、PD、PID 的直觉 | 必须理解 |
| 控制频率和推理频率的区别 | 必须掌握 |
| 超调、震荡、饱和、延迟 | 必须理解 |
| 轨迹插值与单步目标 | 必须掌握 |
| 阻抗控制 | 知道解决什么问题 |
| MPC、最优控制 | 知道存在即可 |
| 完整稳定性推导 | 暂时不需要 |

这部分内容分布在阶段 01 和 03，回答五个问题：

1. 我给机器人的到底是什么？
2. 控制器实际执行的是什么？
3. 为什么目标和实际状态不同？
4. 为什么策略输出不能直接发给电机？
5. 为什么推理 10Hz 不等于控制器也只运行 10Hz？

## 明确跳过的内容

这些每一样都是几年的专业方向，业余投入进去只会得到皮毛，而上层岗位不需要：

- 控制理论深水区（阻抗控制完整推导、力控、MPC）
- 嵌入式与固件开发（MCU、驱动、实时总线）
- 腿足机器人的 locomotion 与步态

- 强化学习的深水区（只讲概念，不调参）
- 点云算法与三维重建

需要的时候，你会知道去找谁。

## 具身与文本 Agent 的四个根本差异

这四条是整个学习过程的主线。技术细节会变，这四条不会。

**1. 世界状态不可回滚。** 后端事务失败可以 rollback，消息可以重投。机器人把杯子打翻了，没有 rollback。幂等/重试机制的前提是「操作可安全重复执行」，这个前提在物理世界直接失效——重试一次抓取，物体已经不在原位了。

**2. 观测不完整且带噪声。** 查数据库拿到的是真值。机器人的每个「观测」都是估计：相机测的位姿有误差，力矩传感器有漂移，编码器有累积偏差。你不知道有没有抓稳，只能从不可靠信号里推断。

**3. 时间是硬约束。** 后端延迟 200ms 是体验问题。控制环 1kHz 意味着 1ms 内必须算完，超了机器人会抖动甚至自激振荡。这不是性能优化，是正确性条件。

**4. 失败是常态，不是异常。** 文本工具调用成功率 88% 算不错。机器人抓取策略在真机上三四成成功率是正常水位。系统设计必须假设大部分动作会失败。

## 最容易出现的学习偏差

**偏差一：过早回到熟悉的 Agent 领域。** 看到机器人任务就马上关注 tool schema、状态管理、HITL、审计、幂等、重试。这些是既有强项，但前期应强迫自己优先问：坐标系对了吗？控制指令是什么单位？动作频率是多少？轨迹是否连续？相机标定了吗？IK 解会不会碰撞？夹爪真的抓住了吗？

**偏差二：模型名字学得比动作空间快。** 不要先陷进 OpenVLA、π0、GR00T 和各种 benchmark。先真正搞清楚：一帧 observation 是什么？一条 action 是什么（绝对角度还是增量）？一个 episode 是什么？模型一次输出一步还是一段？策略运行频率多少？底层控制器怎么执行？

这些比记住模型名字重要得多。

**偏差三：把运行成功当成理解。** 代码跑通不代表懂了。每个实验都要问：去掉某一层会发生什么？去掉关节限位、去掉重新观测、去掉深度噪声、去掉后置核验、降低控制频率、增大推理延迟。通过失败建立的理解通常比通过成功更牢。

## 关于阶段 10 的定位

阶段 10 是把 Agent 运行时治理能力接进具身。它的位置在最后，而且**写成假设而不是答案**。

这个方向的判断本身是成立的：具身领域客观上缺这一层。策略本身没有失败识别能力——阶段 08 的实验会实证这点（给 VLA 一个无意义指令，它照样输出动作），而做策略的人不解决这个问题，做控制的人也不解决。这个空缺独立于学习者是谁。

但「这个方向有空缺」和「我的方案是对的」是两件事。所以阶段 10 里每个想法都配一个实验和一组指标去验证，而不是直接当成结论去实现。

同时，阶段 01 到 09 是必须认真补的。在 VLA 和控制上很难比 CV 博士和十年控制经验的人强，这是现实；但没有这些基础，阶段 10 只会变成用熟悉的词汇重新包装不熟悉的问题。
