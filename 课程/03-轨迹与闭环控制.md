# 阶段 03：轨迹与闭环控制

> 从「终点是什么」到「怎么安全走过去」· 8-12 小时 · 无硬件要求

## 1. 为什么要学

阶段 02 结束时你能求出 IK 解——「要让手到那个点，关节角应该是这些值」。

但你不能把这组值直接赋给机器人。那是传送，不是运动。

**IK 解决「终点关节角是什么」，不解决「中间怎么安全过去」。** 这两件事的区别是本阶段的全部内容，而且必须在引入感知之前搞清楚。否则后面出问题时你无法归因：是感知定位错了，是 IK 无解，还是轨迹撞到了东西？

这一层还回答了 README 里那五个控制问题中的三个：我给机器人的到底是什么、为什么目标和实际状态不同、为什么策略输出不能直接发给电机。

## 2. 学完后必须能回答

- 为什么不能把 IK 求出的 `qpos` 直接赋值给机器人？
- 开环和闭环的区别是什么？`position` 执行器属于哪一种？
- 一个策略以 10Hz 输出动作，底层控制器是不是也只跑 10Hz？为什么？
- 线性插值和五次多项式插值在真机上的差别体现在哪？
- 什么是超调？`kp` 调大会先改善什么、后恶化什么？
- IK 有解但路径撞到障碍物，这个问题该在哪一层解决？
- 一个「技能」（skill）和一次「运动」（motion）的区别是什么？

## 3. 核心概念

### 3.1 三个时间尺度 `[MUST]`

这是本阶段最重要的一张图。搞混这三层，后面所有关于延迟和频率的困惑都源于此。

```
策略 / 规划层        1-50 Hz      「去抓那个红方块」
      │
      │  下发目标位姿或目标关节角
      ▼
轨迹生成层          50-200 Hz    把目标插值成一串中间点
      │
      │  下发单步目标
      ▼
控制器（PD/PID）    500-1000 Hz  让电机实际跟上这个目标
      │
      │  力矩 / 电流
      ▼
    电机
```

**关键认知：策略以 10Hz 输出，不代表控制器也只跑 10Hz。**

策略每 100 毫秒给一个新目标，中间这 100 毫秒里控制器仍在以 1kHz 反复计算「当前位置和目标差多少，该给多大力矩」。如果控制器也只跑 10Hz，机器人会抖得像卡帧的动画。

💡 这个分层和后端的「业务层 / 编排层 / 数据面」结构同构：上层可以慢、可以重试，下层必须快、不能阻塞。

### 3.2 开环与闭环 `[MUST]`

**开环**：下发指令，不看结果。`<motor>` 执行器就是开环——你给多少力矩，它就给多少，不管实际转到哪了。

**闭环**：测量实际状态，根据误差调整输出。`<position>` 执行器内部是闭环的。

```
开环：  目标 ──────────────────► 电机
闭环：  目标 ──► [比较] ──► 电机 ──┬──► 实际
                  ▲               │
                  └───── 测量 ────┘
```

阶段 01 你观察到「实际角度永远追不上目标角度」，那就是闭环控制器在工作但还没收敛。开环连这个「追」的动作都没有。

### 3.3 P、PD、PID 的直觉 `[UNDERSTAND]`

不推导，只要直觉。误差 `e = 目标 - 实际`：

| 项 | 作用 | 调大的后果 |
|---|---|---|
| **P**（比例，`kp * e`） | 误差越大，力越大 | 响应快，但会超调、震荡 |
| **D**（微分，`kd * de/dt`） | 误差变化快时刹一下 | 抑制震荡，但对噪声敏感 |
| **I**（积分，`ki * ∫e`） | 累积长期误差 | 消除稳态误差，但会积分饱和 |

机器人位置控制大多用 PD，不加 I。原因是重力造成的稳态误差通常用重力补偿单独处理，比积分项更直接。

四个必须能识别的现象：

- **超调**（overshoot）— 冲过目标再回来。`kp` 太大或 `kd` 太小
- **震荡**（oscillation）— 在目标附近来回摆。`kp` 太大
- **饱和**（saturation）— 控制输出撞到上限，再增大误差也没用。这时系统实际是开环的
- **延迟**（latency）— 从下发到响应的时间差。延迟会把稳定的系统变成不稳定的

### 3.4 关节空间轨迹与笛卡尔空间轨迹 `[MUST]`

两种插值方式，结果完全不同：

**关节空间插值** — 在起点和终点的关节角之间插值。简单、一定不会 IK 无解，但末端走的路径是弯的，不可预测。

**笛卡尔空间插值** — 在起点和终点的末端位姿之间插值，每个中间点都求一次 IK。末端路径是直线（可预测），但中间可能遇到 IK 无解或奇异位形。

什么时候用哪个：

| 场景 | 选择 | 原因 |
|---|---|---|
| 大范围移动（从 A 区到 B 区） | 关节空间 | 快、稳、不关心路径形状 |
| 接近物体、插入、沿表面移动 | 笛卡尔空间 | 必须保证末端走直线 |
| 抓取时的最后几厘米 | 笛卡尔空间 | 必须垂直下降，否则会推倒物体 |

### 3.5 平滑性：为什么要五次多项式 `[MUST]`

线性插值的问题不在位置，在**导数**。

```
线性插值：   位置连续，速度在起止点突变（从 0 跳到 v）
             ↓
           加速度在起止点是无穷大（冲击）
             ↓
           真机上表现为顿感、抖动、机械冲击
```

五次多项式（quintic）让位置、速度、加速度在起止点全部连续：

```python
def quintic_scaling(t_normalized: float) -> float:
    """五次多项式时间缩放函数。

    s(t) = 6t^5 - 15t^4 + 10t^3

    满足 s(0)=0, s(1)=1, s'(0)=s'(1)=0, s''(0)=s''(1)=0。
    也就是起止点的速度和加速度都为零，因此没有冲击。

    这是「最小 jerk 轨迹」的常用近似。jerk 是加速度的导数，
    人体感知的「顺滑」主要和 jerk 有关，这也是为什么
    电梯和汽车的舒适性设计都在优化 jerk。
    """
    t = t_normalized
    return 6 * t**5 - 15 * t**4 + 10 * t**3
```

三种插值的对比：

| 方法 | 位置 | 速度 | 加速度 | 真机表现 |
|---|---|---|---|---|
| 线性 | 连续 | 突变 | 无穷 | 明显顿感 |
| 三次（cubic） | 连续 | 连续 | 突变 | 轻微顿感 |
| 五次（quintic） | 连续 | 连续 | 连续 | 平顺 |

### 3.6 速度与加速度限制 `[MUST]`

有了平滑的形状还不够，还要保证不超过硬件能力。

```python
"""带速度与加速度约束的轨迹生成。

给定起点、终点和约束，算出最短可行时间，再按这个时间生成轨迹。
这比「固定时长」的做法更实用——短距离移动不该和长距离花一样久。
"""

import numpy as np


def compute_min_duration(
    q_start: np.ndarray,
    q_end: np.ndarray,
    max_velocity: np.ndarray,
    max_acceleration: np.ndarray,
) -> float:
    """计算满足速度和加速度约束的最短运动时间。

    对五次多项式轨迹，峰值速度和峰值加速度有闭式关系：
      峰值速度     = 1.875 * Δq / T
      峰值加速度   = 5.7735 * Δq / T^2

    这两个系数是五次多项式 s(t) 的一阶和二阶导数最大值，
    分别在 t=0.5 和 t≈0.21 处取得。不用记推导，记结论即可。

    返回所有关节中要求最长的那个时间——木桶效应，
    整条轨迹必须等最慢的关节。
    """
    delta = np.abs(q_end - q_start)

    # 避免除零：完全不动的关节不产生时间约束
    moving = delta > 1e-9
    if not moving.any():
        return 0.0

    # 速度约束下的最短时间
    t_vel = np.max(1.875 * delta[moving] / max_velocity[moving])
    # 加速度约束下的最短时间
    t_acc = np.max(np.sqrt(5.7735 * delta[moving] / max_acceleration[moving]))

    return float(max(t_vel, t_acc))


def generate_trajectory(
    q_start: np.ndarray,
    q_end: np.ndarray,
    max_velocity: np.ndarray,
    max_acceleration: np.ndarray,
    control_hz: float = 500.0,
) -> np.ndarray:
    """生成满足约束的关节空间轨迹。

    返回形状 (num_steps, n_joints)。步数由控制频率和时长决定——
    注意这里用的是控制频率而不是策略频率，因为轨迹要喂给控制器。
    """
    duration = compute_min_duration(q_start, q_end, max_velocity, max_acceleration)
    if duration <= 0.0:
        return q_start.reshape(1, -1)

    num_steps = max(2, int(duration * control_hz))
    t = np.linspace(0.0, 1.0, num_steps)
    s = 6 * t**5 - 15 * t**4 + 10 * t**3

    # 广播成 (num_steps, n_joints)
    return q_start + s[:, None] * (q_end - q_start)
```

⚠️ 需核实：那两个系数（1.875 和 5.7735）是五次多项式的标准结果，但如果你换成其他时间缩放函数（比如梯形速度曲线），系数不同。换函数时要重算。

### 3.7 技能：把运动包装成有契约的单元 `[MUST]`

一次运动（motion）是「从 A 移到 B」。一个技能（skill）是「完成一件有意义的事，并且能判断自己成功了没有」。

区别在于技能有**前置条件**和**后置条件**：

```python
"""技能的最小契约。

这个抽象是阶段 05 状态机的基础，也是阶段 06 里
LLM 能调用的工具的基础。现在先建立它。
"""

from dataclasses import dataclass, field
from enum import Enum


class SkillOutcome(str, Enum):
    """技能执行结果。

    刻意区分四种而不是简单的成功/失败：
    每一种对应不同的上层应对策略。
    """

    SUCCESS = "success"
    # 前置条件不满足，没有执行任何动作，世界未改变
    PRECONDITION_FAILED = "precondition_failed"
    # 执行过程中失败，世界可能已改变
    EXECUTION_FAILED = "execution_failed"
    # 动作执行完了，但后置条件校验不通过（静默失败）
    POSTCONDITION_FAILED = "postcondition_failed"


@dataclass
class SkillResult:
    """技能结果。

    world_changed 是物理世界特有的字段。
    PRECONDITION_FAILED 时它是 False（安全重试），
    其余失败时它是 True（必须重新观测）。
    """

    outcome: SkillOutcome
    message: str
    world_changed: bool = False
    measurements: dict[str, float] = field(default_factory=dict)

    @property
    def success(self) -> bool:
        return self.outcome == SkillOutcome.SUCCESS
```

`POSTCONDITION_FAILED` 这一项值得单独指出：**动作执行完了但结果不对**。这是物理系统里最危险的一类失败，因为下游会以为一切正常继续往下走。阶段 05 会专门处理它，阶段 10 会把它作为一个研究假设去量化。

## 4. 最小实验

三个实验，从看现象到建立技能层。

### 实验 A：三种插值的对比

用阶段 01 的 Panda 模型，让末端从一个位置移到另一个位置，分别用线性、三次、五次插值。

记录每一步的实际关节角，然后用数值微分算出速度和加速度序列，画三张图。

```python
def numerical_derivative(series: np.ndarray, dt: float) -> np.ndarray:
    """数值微分。

    用中心差分而不是前向差分，因为中心差分的误差是二阶的。
    边界用单侧差分补齐。
    """
    return np.gradient(series, dt, axis=0)
```

你要看到的：位置曲线三者都平滑，但加速度曲线上线性插值在起止点有尖峰，五次插值是平滑的钟形。

### 实验 B：速度约束生效

用 `generate_trajectory` 生成两段轨迹：一段移动 10 度，一段移动 90 度。

验证两件事：短距离用的时间更短（不是固定时长），以及两段轨迹的峰值速度都没超过 `max_velocity`。

### 实验 C：关节空间 vs 笛卡尔空间

让末端从 `(0.4, -0.2, 0.4)` 移到 `(0.4, 0.2, 0.4)`——同一高度，左右平移。

分别用两种插值，把末端每一步的实际位置记下来画出轨迹：

- 关节空间插值：末端画出一条弧线（可能中间还下沉了）
- 笛卡尔空间插值：末端走直线

**这个实验解释了为什么抓取的最后几厘米必须用笛卡尔插值。** 如果用关节空间，夹爪可能斜着切进去把物体推倒。

## 5. 故障实验

每个实验都是拆掉一层，看会怎么坏。

### 故障 1：直接赋值 `qpos`

跳过轨迹生成，把 IK 解直接写进 `data.qpos`。

**观察什么**：机器人瞬移。如果手里夹着物体，物体会因为速度突变被甩出去（MuJoCo 会算出巨大的接触力）。这直观演示了为什么需要轨迹。

### 故障 2：控制频率降到策略频率

把控制循环从 500Hz 降到 10Hz（每步 `mj_step` 100 次再更新一次 `ctrl`）。

**观察什么**：机器人从平滑运动变成一顿一顿的跳跃。这是「策略 10Hz 就够了吧」这个想法的直接反驳。

### 故障 3：`kp` 扫描

固定轨迹，把 `position` 执行器的 `kp` 依次设成 1、10、100、1000，记录实际角度对目标角度的跟踪曲线。

**观察什么**：
- `kp=1` — 严重滞后，根本跟不上
- `kp=10` — 有滞后但能跟
- `kp=100` — 跟得紧，可能开始有轻微超调
- `kp=1000` — 超调明显，或者开始震荡

把四条曲线画在一张图上。这张图是你对 P 控制的直觉来源。

### 故障 4：取消速度约束

把 `max_velocity` 设成一个很大的值（比如 100 rad/s），跑实验 B 的 90 度移动。

**观察什么**：轨迹时长被压到极短，关节速度爆炸。在仿真里可能只是看起来很快，但这个指令给真机会导致舵机堵转、过流、发热。

### 故障 5：笛卡尔插值穿过奇异位形

选一对起终点，让中间路径经过机械臂完全伸直的位置（奇异位形）。用笛卡尔插值。

**观察什么**：IK 在中间某几步失败，或者求出的关节角突然剧变（关节以极高速度翻转）。这解释了为什么笛卡尔插值需要配合奇异位形检测。

### 故障 6：IK 有解但路径碰撞

在桌面上放一个障碍物，选一对起终点，使得直线路径穿过障碍物。用笛卡尔插值。

**观察什么**：IK 每一步都有解，轨迹生成也成功，但机械臂撞上障碍物。

**这个实验回答了一个重要问题**：碰撞不是 IK 该解决的问题，也不是轨迹插值该解决的问题——它属于**运动规划**（motion planning，如 RRT、PRM）。本阶段不实现运动规划，但你必须知道这个缺口在哪，否则会误以为「IK 通了就没事了」。

## 7. 与 Agent / 后端的类比

**三个时间尺度 ↔ 分层架构。** 策略层（秒级、可重试）、轨迹层（毫秒级）、控制器（微秒到毫秒级、硬实时），对应后端的业务编排层 / 服务层 / 数据面。上层慢而聪明，下层快而简单。

**闭环控制 ↔ reconcile 循环。** PD 控制器在做的事就是「测量当前状态，和期望状态比较，输出修正」。这和 Kubernetes controller 的 reconcile 是同一个模式，只是频率高了几个数量级。

**技能的前置/后置条件 ↔ 接口契约。** 前置条件是入参校验，后置条件是返回值断言。`POSTCONDITION_FAILED` 对应「接口返回 200 但数据实际没写进去」。

**速度与加速度约束 ↔ 限流。** `max_velocity` 是速率限制，`max_acceleration` 是速率变化的限制。后者在后端里对应「不要瞬间把 QPS 从 100 提到 10000」——慢启动。

**饱和 ↔ 背压。** 控制输出撞到上限后再增大误差也没用，系统实际变成开环。这对应队列满了之后再往里塞消息只会丢——你必须在上游降速，而不是在下游加大力度。

## 8. 这个类比在哪里失效

上面每个类比都有边界，越过边界会让你判断错误。

**「闭环控制就是 reconcile」失效在时间约束上。** reconcile 循环慢一点只是收敛慢，控制环慢一点会导致系统**不稳定**——不是慢，是发散、震荡、损坏硬件。控制理论里有严格的稳定性判据（相位裕度、增益裕度），reconcile 没有对应概念。这也是为什么控制器不能用 Python 写、不能有 GC 暂停。

**「限流就是速度约束」失效在违约后果上。** 后端超过限流阈值，请求被拒绝或排队，系统仍然正确。机器人超过速度约束，舵机堵转发热、齿轮磨损、物体被甩出去——**没有「优雅拒绝」这个选项**，物理系统会以损坏的方式承接你的错误指令。所以限制必须在下发前强制，不能靠事后监控。

**「接口契约就是前置后置条件」失效在可验证性上。** 后端的返回值断言是确定的：`user_id` 要么存在要么不存在。物理世界的后置条件是带容差的模糊判断——「杯子在架子上」实际是「在目标位置 ±3cm 内」。容差设太紧会误报失败，设太松会漏过真实失败（杯子放歪了但还没倒）。**你必须自己选这个阈值，而且没有正确答案。**

**「分层架构」失效在跨层信息流上。** 后端的分层是单向的：上层调下层，下层不关心上层。控制层必须把「我跟不上了」这个信息传回上层——如果轨迹要求的速度超出能力，上层需要知道并重新规划。这是一条必需的反向通道，而后端分层里很少有这种设计。

**一个更根本的差异：** 后端的每一层都可以假设下层「要么成功要么报错」。控制层给不了这个保证——它总是给你一个「差不多到位了」的结果，误差是常态而不是异常。你的所有上层逻辑都要建立在「下层永远有误差」这个前提上。
