# 岗位方向与能力地图

用来回答两个问题：**我要去的岗位要什么能力？这个项目的哪一步在补哪一块？** 学习顺序仍以 [PROGRESS](../PROGRESS.md) 和 [CURRENT_TASK](../experiments/highway_driving/CURRENT_TASK.md) 为准。

公开资料核对于 2026-08-28，求职目标更新于 2026-09-27。引用岗位前要重新核实是否还在招。

## 1. 目标

- **公司类型**：车企自己的智能驾驶团队（看清所属团队、劳动合同主体、子公司 / 合资关系）。
- **城市**：杭州优先，上海其次（按实际办公地点，不按总部）。
- **薪资**：月薪 20k 以上（税前 / 税后、几个月待确认）。
- **不算同一目标**：供应商、Robotaxi 服务商、外包驻场、车企里的 IT / 座舱 / 营销 AI 岗。可以作为参考，但不当作主要目标。

核对一个岗位时，记录：招聘类型（校招 / 社招）、城市、团队、硬性条件、核心能力、薪资口径。校招资格按学位授予时间和企业批次核对。

## 2. 两条切入路径

### 路径 A：先进“桥梁”岗位（和现在的经验衔接更顺）

```text
驾驶数据与评测 → 场景挖掘 / 数据闭环 → 仿真评测平台 → 模型训练与推理工程 → 部署与可观测性
```

对应岗位：智驾数据价值与数据闭环、自动化评测与仿真、训练 / 推理平台、端到端算法工程支持。

你的后端交付、数据处理和评测经验在这里直接有用。这个项目的阶段 2（规则策略 + 批量评测 + 失败分析）就是在做一份仿真评测方向的作品。

### 路径 B：长期进入核心算法（VLA / 端到端）

```text
视觉与几何 → 多相机时序 → 轨迹与车辆运动 → 端到端模型 → 闭环评测 → 驾驶 VLM / VLA → RL / 世界模型
```

两条路不冲突：同一个项目一路积累作品，不必走完一条才能投递。

## 4. 能力地图

| 能力 | 现在 | 怎么教 | 本项目在哪一步补 |
| --- | --- | --- | --- |
| Python 工程 | 已有 | 直接用 | 全程 |
| Agent / workflow | 已有 | 作类比，说明在物理世界哪里失效 | 全程 |
| 深度学习训练、Transformer | 已有 | 放进驾驶任务里验证 | 阶段 2（DQN）、阶段 3 |
| 蒸馏、量化 | 已有 | 后期做驾驶模型的压缩部署实验 | 远期 |
| C++ | 学过 | 读改一个真实模块，从那里恢复 | 按岗位需要 |
| Linux / Git / 调试 | 已有 | 不单独开课 | 全程 |
| 车辆运动学、控制 | **新学** | 从模拟器源码和实验开始 | 阶段 1（进行中） |
| 闭环交互、评测方法 | **新学** | 固定种子、结束原因、批量评测 | 阶段 1–2 |
| 跟车与变道规则（IDM / MOBIL） | **新学** | 读源码，再自己写规则 | 阶段 1–2 |
| 强化学习 | 未学 | 闭环清楚后再进入 | 阶段 2（DQN 对比） |

| 驾驶 VLM / VLA | **新学** | 有了数据、模型、评测基础后再进入 | 远期 |
| 安全边界、ODD、fallback | **新学** | 和闭环评测一起建立 | 远期 |

能力分级（用来判断深度）：

```text
L1 见过：知道名词和用途
L2 能解释：能画出数据链，指出常见失败
L3 能控制：能实现、修改、测试、评测、排错
L4 能权衡：能设计对照实验，比较替代方案
```

目标不是每个方向都做到 L4：**整条链能讲清（L2），选定的一个方向能独立交付（L3），再结合岗位逐步做深。**

## 5. 作品

**近期（阶段 2 结束时）**：一个可以放上 GitHub 的仿真评测小项目——规则策略、多种子批量评测表、失败案例回放、和 DQN 的对比、写清方法和局限的 README。对应仿真评测、预测规划方向。

**长期**：一个公开可复现的综合项目，包含数据契约与可视化、端到端训练和推理、开环与闭环评测、三类以上失败分析、压缩部署前后的行为 / 延迟对比、安全边界与 fallback。

只跑通 README、只展示 loss 曲线、只背模型名字，都撑不起面试。作品要能讲清“为什么这样做、哪里会失败、怎么验证”。

## 6. 不作为主线的方向

纯控制理论研究、SLAM / 高精地图深水区、底盘嵌入式与硬件、真实道路安全员、只做 Prompt 或聊天 Agent 的应用岗。需要时只学最低必要知识。
